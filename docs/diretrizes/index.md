# Guia de coloboração

O objetivo deste guia é estabelecer diretrizes claras para a colaboração eficaz dentro do time, garantir que todos o membros estejam alinhados e trabalhem em direção ao mesmo objetivo - Irá ajugar a entender como vamos trablhar juntos de forma eficaz. 

As regras genéricas estão contidas neste arquivo, **por favor leia!**

---
## Regras de Contribuição
1. Crie uma branch para cada feature: para cada feature que será desenvolvida deve ser criada uma branch, o nome da branch
deve ser o mais próximo possivél da feature que está/será desenvovida. 
2. Commits pequenos e frequentes: os commits devem ser feitos de forma frequentes e clara, faça commit tão logo realizar qualquer alteração. Os commits devem ser feitos depois de realizar qualquer mudança no projeto, nunca esperar um grande número de novas implementações, correções... para realizá-los.
3. Use mensagens de commit claras e consitentes: cada commit deve ser acompanhado de uma mensagem clara e  consitente sobre o que foi feito e, quando possível, como foi feito.

---
## Regras de Código
1. Siga o padrão de código estabelico: para manter o código consistente e fácil de ler, siga o padrão estabelico em [padrão-de-código](docs/code)
2. Teste o código antes de fazer pull request: garanta que o teu código fuciona corretamente, futuramente exigeremos inclusão dos testes.

---
## Regras de comunicação
- **Reuniõs regulares**: realizaremos reuniões regulares de 15-30min para discutir o progresso do projeto, resolver problemas e alinhar expectativas. {Segunda, Sexta}
- **Comunicação aberta e transparente**: devemos manter uma comunicação aberta com time sobre o nosso trabalho, probelmas e preucupações.
- **Ferramentas**: Vamos acabar por emigrar para o trello. O WhatsApp deve ser usado apenas para informações pontuais e superficiais{links, imagens sugestivas e outros}

1. Use **Issues** para discutir mudanças, problemas ou sugestões
2. Use **Pull Requests** para enviar suas contribuições
3. Use @mentions para mencionar outros desenvolvedores: garanta sempre que quem pretende será notificado sobre as mudançãs/sugestões.
4. Comunicação clara e respeitosa.

---
## Regras de revisão de código
1. Faça revisão de código regularmente: garanta a qualidade do códgio e que ele segue o padrão estabelecido
2. Forneça feedback: ajude a melhorar opinando

---
## Outras
1. Mantenha o código atualizado: evite conflitos e garanta que estajas trabalhando com a mesma versão do código/versão-mais-recente.
2. Documente o processo de desenvolvimento: faça os outros desenvolvedores entenderem o que estás a fazer, como funciona e como contribuir.
